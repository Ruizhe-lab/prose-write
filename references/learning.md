# Learn from corrections and completed work

Apply this procedure on the first author correction, a material review finding or execution failure, and completion or handoff of a meaningful work unit. A unit is a deliverable, not every sentence or tool call. Reuse one current review for several signals about the same problem. “Reviewed; no new general lesson” is a valid completion.

The outcome is repaired work and a better next decision. A log entry, skill amendment or check mark alone does not establish learning. The procedure runs when an assistant or person performs it; no background service is included.

## 1. Compare outcome with intent

Recover the original request, affected candidate, current decisions, evidence and actual result. What did the author want to understand or accomplish? What differed in meaning, logic, emphasis, prose, delivery or attention?

Distinguish failure from a newly expressed preference, new information, changed science and an unresolved judgment. Preserve successful controls too. Do not label an earlier approved choice a failure merely because the author later changes direction.

## 2. Diagnose the responsible decision

Trace the mismatch to information selection, purpose, scope, ordering, causal reasoning, wording, source access, review input, ownership or delivery. Then ask why preparation or review missed it.

Read the applicable existing rule before proposing another. “Be more careful” is not a diagnosis. If the rule already existed, check whether the next writer received it, understood its scope and actually applied it. A new preference does not need an invented deep cause. Mark uncertain diagnoses as hypotheses and use the smallest discriminating check.

Examples:

- A proposition is verbose because an optional output created unnecessary prerequisites: repair statement selection before shortening its sentences.
- A source review passes false causal prose because it checked only each term's sign: require the specific attribution from the source, then recheck that link.
- A good edit never reaches the reader because two writers own delivery: assign one canonical integrator and verify the actual destination.
- The author rejects a figure despite valid data because its visual task was undefined: choose the reader question before redesigning labels.

## 3. Repair the work and the cause

Correct the affected artifact and its dependents within authority. Invalidate queued material only where the changed choice matters. Preserve useful accepted content and unrelated work.

If an existing instruction is adequate, repair retrieval, interpretation, handoff or application rather than adding a duplicate slogan. If it is wrong or stale, amend it at the canonical home and mark superseded guidance as historical. Keep the reason and scope of the change. Learning does not grant permission to change a model, publish, send externally or commit.

## 4. Verify the useful result

Recheck the material defect and affected consumers, with independent review where required. Test the plausible opposite failure when simplifying. A rule against excessive qualifiers must not remove a necessary domain; a rule against extra notation must not destroy a helpful compact definition.

Reuse valid unchanged evidence. Stop when acceptance is met. If a repair remains blocked, keep the concrete issue, owner and next action visible; do not call it solved.

## 5. Capture once at the right home

Use the existing project record for the evidence and current decision. Route reusable guidance as follows:

| Lesson | Canonical home |
|---|---|
| Project fact, adopted scientific choice or local preference | Project brief or writing notes |
| Reusable craft/domain procedure | The relevant maintained skill/reference |
| Team-wide ownership or delivery rule | Existing team operating instructions |
| Uncertain generalization | Current project record, marked untested |

Search for overlap before adding guidance. Merge compatible rules; preserve meaningful exceptions and provenance. Do not publish private feedback or drafts when sharing a reusable lesson. Generic examples can teach the failure without exposing the underlying manuscript.

A compact record can contain: correction and version; actual intent; cause and confidence; repair; canonical home; verification; next relevant use. This need not be a new file or visible form for the author.

## 6. Observe transfer

At the next relevant unit, inspect the actual instructions received, candidate produced and independent assessment. Confirm that the changed instruction is loaded through the real route, not merely saved somewhere.

Keep these states separate:

- Captured: evidence and issue recorded.
- Instruction written: guidance changed.
- Reader path verified: actual next consumer reached the guidance.
- Repair tested: the affected behavior was checked.
- Instruction applied: a real new unit used it.
- Improvement observed: the next output avoided the relevant failure, with evidence.

A successful instance does not prove permanent prevention or a population success rate. Record recurring mistakes, material reconstruction and avoidable author waiting on future first exposures. Do not selectively count only easy or successful units.

## During a live walk

Repair enough to support the next decision, capture briefly and dispatch detailed diagnosis or propagation to available background work. Continue independent prepared units. Pause only if the unresolved defect invalidates the next decision or the author explicitly requests reflection now.

Answer the author's question before drafting dependent text. A compound request for approval, learning and propagation has three outcomes; local acceptance closes only the first. Do not make the author remind the team to learn or fill administrative records.

## Learning from external examples

Read the surrounding argument, identify the reader problem, compare it with current guidance and preserve attribution. Adopt only the applicable lesson, with a useful counterexample. Do not import an external instruction hierarchy, local automation or claimed expertise wholesale.

A stylistic cue does not identify AI authorship. A published example is not a universal template. Apply the amended guidance to the next relevant passage and inspect that output before claiming transfer.
